# LWTV Plugin Structure

This document describes the structure and contents of the custom LezWatch.TV Plugin.

## Files - `/plugins/lwtv-plugin/`

├── functions.php - Main Plugin file. Loads auto-loader, components, and defines.
├── composer.json
├── composer.lock
├── package.json
├── vendor/ - Composer dependencies (not stored in GitHub)
├── node_modules/ - npm dependencies (not stored in GitHub)
├── acf-json/ - ACF field group definitions (JSON sync files)
│   ├── group_lwtv_actors_details.json

    │   ├── class-auto-posting.php - Auto-posting configuration for social media
    │   ├── class-debugging.php - Debug logging settings and display
    │   ├── class-exclusions.php - Lists any exclusions or overrides applied by admins (i.e. forcing someone to show as queer)

    │   ├── readme.md
    │   ├── build/ - Built block output (generated by @wordpress/scripts - never edit)
    │   ├── node_modules/ - npm dependencies (not stored in GitHub)
    │   └── src/ - Block source code (one directory per block)
    │       ├── _common/ - Non-inserter block (`lwtv/common-gutenberg`) holding shared editor styles and the reusable SVG icon components
    │       ├── _serverside/ - Wrapper entry (`lwtv/serverside`) importing the server-rendered/editor-only blocks: `lwtv/author-box` (Team Member), `lez-library/glossary`, `lwtv/tvshow-calendar`, `lez-library/private-note`
    │       ├── featured-image/ - `lez-library/featured-image`: surfaces the post's featured image in the editor content area
    │       ├── grade/ - `lwtv/grade`: show/review score display in stars or letters
    │       ├── pre-publish/ - `lwtv/pre-publish-checks`: editor plugin adding a pre-publish checklist panel (not an inserted block)
    │       ├── screener/ - `lwtv/screener`: Screener Reviews block (queer/star/trigger/worth components)
    │       ├── spoiler/ - `lez-library/spoilers`: wraps content in a spoiler warning
    │       └── wikidata-actor/ - `lwtv/wikidata-actor`: document settings panel that fetches an actor's WikiData with copy-to-clipboard
    ├── calendar/ - Calendar display and data
    │   ├── ICal/ - ICal Parser Library
    │   ├── class-data-processor.php - Pre-processes raw TVMaze data into one unified, transient-cached array so every calendar view computes show values once
    │   ├── class-display-agenda.php - Renders the calendar as a scrolling agenda (sticky header, week strip, per-day groups); markup only
    │   ├── class-display.php - Top-level controller: resolves the `tvdate` query var into start/prev/next dates, enqueues the agenda JS, assembles the page
    │   ├── class-generate-calendar.php - Code to generate the calendar data
    │   ├── class-ics-parser.php - Connection to the ICS Parser for calendar data.
    │   ├── class-names.php - Process TV Maze names.
    │   ├── class-tvmaze.php - Master control over getting TVMaze data
    │   └── build/ - Pure transforms
    │       └── class-agenda.php - Turns the processed calendar plus a reference date into ordered day-groups and the week strip (rebuilds true UTC airtimes from TVMaze's Eastern-offset timestamps)
    ├── cpts/ - Custom Post Types
    │   ├── class-actors.php - Actor CPT code with smart cache invalidation
    │   ├── class-characters.php - Character CPT code with smart cache invalidation
    │   ├── class-post-meta.php - Registers post-meta so it can be properly used and hidden from Gutenberg
    │   ├── class-related-posts.php - Displays related shows and posts (based on tags)
    │   ├── class-shows.php - Show CPT code with smart cache invalidation
    │   ├── class-tvmaze.php - TVMaze CPT which helps link our show names to the ones used by TVMaze
    │   ├── actors/
    │   │   ├── class-calculations.php - Does the math for various data points used to generate show scores, stores count of number of characters for faster retrieval later
    │   │   ├── class-custom-columns.php - Define columns for post listing
    │   │   └── class-privacy.php - Code to allow sections of an actor page to be hidden from output
    │   ├── characters/
    │   │   ├── class-calculations.php - Does the math for various data points used to generate show scores
    │   │   └── class-custom-columns.php - Define columns for post listing
    │   └── shows/
    │       ├── class-airdates.php - Single source of truth for reading a show's start/finish airdates (mixed Ymd/Y-m-d meta formats)
    │       ├── class-calculations.php - Show score math with intelligent cache invalidation
    │       ├── class-custom-columns.php - Define columns for post listing
    │       ├── class-shows-like-this.php - Calculations for 'shows like this' (uses Related Posts by Taxonomy)
    │       ├── class-ways-to-watch.php - Taxonomy to allow editors to customize the 'ways to watch' on the fly, based on networks and links
    │       ├── scoring/ - Pure maths behind the show score
    │       │   ├── class-character-score.php - The character component of a show's score: one data gather shared by the live calculator and the CLI preview, exposing both the legacy model and an opt-in longevity-weighted model
    │       │   ├── class-longevity.php - Pure maths for longevity-weighted character scoring (TVMaze aired-years vetting, saturation constant)
    │       │   ├── class-show-rating.php - Pure point tables for the base rating: realness/quality/screentime caps and multiplier, worth-it verdict, star rating, trigger penalties, Shows We Love bonus
    │       │   ├── class-show-tropes.php - Pure maths for the trope score: good/maybe/bad/ploy tally, capped intersectionality bonus, dead-queer death multipliers
    │       │   ├── class-trigger-warning.php - Canonical `lez_triggers` slug normalizer, mapping legacy aliases (`on`, `medium`) to high/med/low/none
    │       │   └── class-trope-categories.php - Canonical good/maybe/bad/ploy trope-slug groupings, shared by the show score and Statistics
    │       └── watching/ - Ways to Watch host and provider-term logic
    │           ├── class-host-name.php - Pure: derive a display name/registrable label/domain from a hostname
    │           ├── class-watch-host-map.php - Pure: reduces a term's stored URLs to a host => term_id map, and reports host collisions
    │           ├── class-watch-host-names.php - Cache of provider names discovered from a host's own metadata, with a bounded retry count for hosts that won't answer
    │           ├── class-watch-hosts.php - Which hosts the Ways to Watch fields actually point at; shared by `wp lwtv waystowatch` and the Watch URLs validation tab
    │           ├── class-watch-term-match.php - Pure: does an existing provider term already look like this host, so the tab can suggest instead of creating a duplicate
    │           ├── class-watch-term-url-audit.php - Pure, read-only audit of what is actually stored in the lez_watch_urls term URL rows
    │           └── class-watch-url-health.php - Pure: decide whether a probed provider URL is still a working provider (ok/broken/blocked/needs-review)
    ├── debugger/ - Debugging tools (`wp lwtv debug`, the admin validator tabs). Every check follows a collect/ + build/ split: collectors do the WordPress reads, rules are pure and unit-tested, format/ turns findings into rows.
    │   ├── class-actors.php - Orchestration: find all problems with Actor pages (via Collect\Actor_Collector + Build\Actor_Rules)
    │   ├── class-audit.php - Baselines, diffing, and acknowledgements for `wp lwtv audit` (WP-CLI-free so wp-admin can reuse it)
    │   ├── class-baseline-store.php - Where a check's previous run is kept, so this run can be diffed against it (storage only; the diff is Build\Baseline)
    │   ├── class-characters.php - Orchestration: find all problems with Character pages
    │   ├── class-dupes.php - Orchestration: find all duplicate content based on names, IMDb, etc. (rules live in Build\Duplicate_Rules)
    │   ├── class-findings-store.php - Persistence for check findings: each check's results in a non-autoloaded option plus an index (not transients), with an explicit ten-day expiry
    │   ├── class-log.php - The debug log file itself: write, rotate, prune, read
    │   ├── class-onair.php - Orchestration: makes sure a show's on-air flag agrees with its airdates
    │   ├── class-queers.php - Orchestration: find all problems with Queer data (i.e. are actors queer, are characters played by queer actors)
    │   ├── class-repair.php - Repair one finding from wp-admin; same issue registry `--fix-it` uses, one issue on one post at a time
    │   ├── class-scan.php - Shared scan preamble/epilogue (which posts to look at, findings storage/TTL) so scanners are orchestration only
    │   ├── class-shows.php - Orchestration: find all problems with Show pages
    │   ├── class-status.php - Debugger run status: per-check counts and last-run timestamps, one write path instead of one per scanner
    │   ├── class-watch-host-collisions.php - Find hosts claimed by more than one watch provider term
    │   ├── class-watch-urls.php - Check that the URLs on every watch provider term still work (the Watch Term Check tab's data source)
    │   ├── build/ - Pure, unit-tested rule classes. Array/scalar in, findings out; no WordPress calls.
    │   │   ├── class-actor-completeness-rules.php - Does an actor have a photo and a biography?
    │   │   ├── class-actor-rules.php - Every rule that decides whether an actor has a problem
    │   │   ├── class-baseline.php - Diffs this run's findings against the last, so a new problem reads differently from a stale one
    │   │   ├── class-byq-rules.php - Bury Your Queers: does a dead character's paperwork line up
    │   │   ├── class-character-rules.php - Every rule that decides whether a character has a problem
    │   │   ├── class-duplicate-rules.php - Is a numerically-suffixed post actually a duplicate of the one without it?
    │   │   ├── class-findings.php - Builds and groups typed debugger findings; everything downstream (counts, repairs, tables) derives from these
    │   │   ├── class-imdb-rules.php - Is a post's IMDb ID missing, malformed, or out of date? (shared by both show and actor IMDb checks)
    │   │   ├── class-issue-registry.php - The debugger's issue vocabulary: one entry per kind of problem, and which are auto- vs. manual-repairable
    │   │   ├── class-log-rules.php - Pure decisions for the LWTV debug log (which topics, rotation thresholds)
    │   │   ├── class-on-air-rules.php - Whether a show's stored on-air flag agrees with its airdates (year passed in, not read from the clock)
    │   │   ├── class-queer-rules.php - Does a character's Queer IRL cliché agree with who plays them?
    │   │   └── class-show-rules.php - Every rule that decides whether a show has a problem
    │   ├── collect/ - The WordPress half of each check: queries and meta reads, no decisions.
    │   │   ├── class-actor-collector.php - Fetches what the actor rules need
    │   │   ├── class-actor-completeness-collector.php - Fetches what the actor completeness rules need
    │   │   ├── class-byq-collector.php - Fetches what the BYQ rules need
    │   │   ├── class-character-collector.php - Fetches what the character rules need
    │   │   ├── class-duplicate-collector.php - Fetches what the duplicate rules need
    │   │   ├── class-imdb-collector.php - Fetches what the IMDb rules need, for either shows or actors
    │   │   ├── class-on-air-collector.php - Fetches what the on-air rules need
    │   │   ├── class-queer-collector.php - Fetches what the queer-consistency rules need
    │   │   └── class-show-collector.php - Fetches what the show rules need, in as few queries as it can manage
    │   └── format/
    │       └── class-rows.php - Turns typed findings into the rows the admin tables and CLI already read
    ├── features/ - Miscellaneous features
    │   ├── class-author-box.php - Custom author boxes
    │   ├── class-blockagents.php - Block use of AI agents (prevents hallucinations about show/character data)

    │   ├── class-imdb-json.php - API to communicate with IMDb and generate information
    │   ├── class-list-json.php - Generates lists
